Phase 0 — Scaffolding

Snakemake project skeleton, pixi env (geopandas, igraph, snkit, pyrosm/osmium, xarray, rasterio). Mirror Open-GIRA's structure since you'll borrow rules.

We're just working locally for now; set up a git repo but don't work with any kind of origin/remote.

Phase 1 — Multimodal graph

The biggest chunk. Three layers plus interconnects.

Road + rail + maritime via Open-GIRA. Clone nismod/open-gira v0.3.0+, run their network-creation rules on a recent OSM planet file. Output: GeoPackage with edges/nodes for each mode, country-tagged, speeds gap-filled by road class. Maritime is port-to-port from AIS-derived vessel movements.

Inland waterway layer (custom). This is the gap Open-GIRA doesn't fill and it matters for ERW. Don't try to extract all navigable rivers from OSM/HydroSHEDS — you'll spend ages cleaning. Hand-encode the ~20–30 systems that actually move bulk freight: Mississippi-Ohio-Illinois-Tennessee, Great Lakes/St. Lawrence Seaway, Rhine-Main-Danube-Rhône, Elbe, Yangtze, Pearl, Grand Canal, Volga-Don-Kama, Ob-Irtysh, Yenisei, Amur, Paraná-Paraguay, lower Amazon, Mekong, Mahanadi/Brahmaputra. CEMT class for Europe, similar classifications elsewhere — these set the max barge tonnage and thus per-tkm cost. Reference: PIANC database, USACE for US, CCNR for Rhine. Encode as line segments in the same schema as the other modes.

Transshipment edges. At every port and at rail-yard nodes adjacent to road/water, add zero-length edges with fixed cost and CO2 per tonne handled. Empirically: $1–3/t handling, ~5–10 kg CO2/t per transshipment. These penalties are what make multimodal routing realistic — without them, the optimizer flips between modes spuriously.

Output: single igraph Graph object pickled, with edge attributes mode, length_km, country, plus geometry preserved separately as GeoPackage for inspection.

Phase 2 — Edge attributes for cost & CO2

Two numbers per edge plus length. Data compilation is the time sink, not coding.

CO2 factors (g CO2/tkm, well-established):

    Heavy truck bulk: 60–80
    Rail electric: 12 (Europe avg) to 25 (China grid avg); diesel rail: 28
    Inland barge by CEMT class: 25–40
    Sea bulk carrier (Capesize/Panamax loaded): 3–5; Handysize short-sea: 8–12

Build a small lookup keyed on (mode, country) for grid-mix-dependent values. EcoTransIT publishes the methodology; cite IMO 4th GHG Study for marine, IEA for land. Apply factor × edge length.

Cost factors for bulk minerals specifically (USD/tkm), which is much lower than general freight literature:

    Truck: $0.05–0.10 (highly country-dependent — use Verschuur 2025 Zenodo deposit's per-country road cost factors as a starting point and scale)
    Rail unit train: $0.01–0.03
    Barge: $0.005–0.01
    Ocean bulk: $0.002–0.005

Cross-check with Renforth (2012) and Eufrasio et al. (2022) which give ERW-specific transport assumptions, plus the World Bank LPI for country adjustments. Bulk-rate quotes from Argus or Drewry if accessible. Be explicit that these are ~2020–2024 USD; commodity transport rates are volatile.

Edge cost = unit_cost(mode, country) × length_km. Transshipment cost added at the relevant zero-length edges.

Phase 3 — Source/destination snapping API

Function snap(lon, lat, mode_preference=None) → node_id. Default snaps to nearest road node within X km. mode_preference="rail" snaps to nearest rail terminal — important because some quarries and most steel plants have direct rail loadout, which changes the answer dramatically.

For the destination side at 0.5° you have ~64k land cells; filter to those with non-trivial cropland coverage (SPAM 2020 or ESA WorldCover ≥ ~5% cropland) — this gives ~30–40k cells. Each gets snapped once to the nearest road node and cached.

Phase 4 — Routing

For each source: three independent SSSP runs in igraph, weights = length_km, cost_total, co2_total respectively. Cost and CO2 routes are computed separately (the minimum-cost path and minimum-CO2 path generally differ — that difference is informative).

Output per source: three vectors of length ~30–40k. Don't store paths, just terminal values. Per-source output: ~0.5 MB. For ~10³ sources: ~500 MB total. Trivial.

Output format: one xarray DataSet per source with three DataArrays on the destination cell grid, written to NetCDF or zarr. Or stack into a single 3D array indexed by (source_id, dest_cell, metric). Zarr is more friendly for downstream optimization that may only read slices.

Phase 5 - Visualization

Build a simple but good-looking local web interface with a map where the user can select a source location and the map is shaded by transportation cost or CO2 emissions on a grid cell level.
